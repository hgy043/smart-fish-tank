# 板级支持包的来源查证 —— `[小智]` 其实是立创的开发板

> **日期**：2026-10-14
> **范围**：查证本项目引为真源的两套板级代码，其**来源是否独立**
> **结果**：查明 `gec-esp32s3-board/` 是 `lichuang-dev/` 的副本；
> 本项目文档里多处「两套厂家代码一致」的表述因此需要更正（**结论未变，论证强度要重估**）

---

## 1. 一句话结论

本项目一直把两套板级代码称作「**两套厂家资料**」并用「两者一致」给引脚结论背书：

| 记号 | 路径 | 本项目原先认为 |
|---|---|---|
| `[小智]` | `xiaozhi-esp32-1.9.4-gec/main/boards/gec-esp32s3-board/` | 粤嵌的 xiaozhi 板级适配 |
| `[06BSP]` | `06-tcp_client_bafa_mqtt/main/esp32_s3_gec.{c,h}` | 粤嵌官方 BSP |

**`[小智]` 不是粤嵌写的。** 它是同一仓库里 `main/boards/lichuang-dev/`
（**立创 / 嘉立创开发板**）的副本：粤嵌改了名字、加了自己的注释，
`config.h` 则只删掉了开头那段写着「立创开发板硬件配置头文件」的署名。

⇒ **「两套厂家代码一致」这个说法在部分项上不成立**，因为其中一套根本不是粤嵌的资料。
见第 3 节逐项重估。

---

## 2. 证据

三个文件全部比对，`main/boards/` 之下两个目录：

### 2.1 `config.json`

```diff
5c5
<             "name": "lichuang-dev",
---
>             "name": "gec-esp32s3-board",
```

**只差一个字段**，其余逐字节相同。

### 2.2 `config.h`

```diff
1,5d0
< /**
<  * @file config.h
<  * @brief 立创开发板硬件配置头文件
<  * @details 该文件定义了立创开发板的所有硬件引脚配置、参数设置和功能选项
<  */
```

**只差开头这 5 行，而它们正是署名注释。** 删掉后文件逐字节相同 ——
也就是说，**全部引脚宏（`AUDIO_I2S_GPIO_*` / `BUILTIN_LED_GPIO` /
`DISPLAY_BACKLIGHT_OUTPUT_INVERT` / `DISPLAY_WIDTH` …）与立创版一模一样**。

### 2.3 `gec_esp32s3_board.cc`

类骨架完全对应（行号仅因粤嵌增补注释而后移 1~7 行）：

| 立创 | 粤嵌 |
|---|---|
| `class Pca9557 : public I2cDevice`（:38） | 同名同类（:39） |
| `class CustomAudioCodec : public BoxAudioCodec`（:74） | 同名同类（:76） |
| `class LichuangDevBoard : public WifiBoard`（:129） | `class GecEsp32s3Board : public WifiBoard`（:131） |
| `DECLARE_BOARD(LichuangDevBoard);`（:491） | `DECLARE_BOARD(GecEsp32s3Board);`（:498） |

**把两个文件去掉全部注释与空白后再比 `Pca9557` 类，只差一处换行**
（构造函数初始化列表的断行位置）—— **连寄存器写入值都完全相同**。
粤嵌做的是：改类名与文件名、重排 include、**增加了大量 doxygen 注释**。

> 那些新增的注释很关键：它们让这份转抄品看起来像一份**针对本板写的**厂家资料。
> 例如 `#define DISPLAY_BACKLIGHT_OUTPUT_INVERT true // 背光输出反转：启用(低电平有效)`
> —— 行尾说明是转抄时补的，并不是粤嵌对自己硬件的描述，而本项目实测是**高电平点亮**。

### 2.4 时间戳同向

| 文件 | 立创 | 粤嵌 |
|---|---|---|
| `config.json` | 2025-11-04 | 2026-02-25 |
| `config.h` | 2026-01-25 | 2026-02-25 |
| `*.cc` | 2026-02-24 | 2026-03-09 |

粤嵌版全部晚于立创版。

### 2.5 复现命令

```bash
cd <xiaozhi 工程>/main/boards
diff lichuang-dev/config.json gec-esp32s3-board/config.json
diff lichuang-dev/config.h   gec-esp32s3-board/config.h
diff lichuang-dev/lichuang_dev_board.cc gec-esp32s3-board/gec_esp32s3_board.cc
```

## 3. 这改变了什么：逐项重估

「两处数字一致」只有在**两者独立**时才构成互证。更正后：

| 取值 | `[06BSP]`（粤嵌自己的）是否也确认 | 现在的强度 |
|---|---|---|
| LCD：DC=IO39 / MOSI=IO40 / SCLK=IO41 / BL=IO42 | ✅ 确认 | **不变** —— 仍是两个独立来源，且已上板实测 |
| I2S：BCLK=IO14 / WS=IO13 / MCLK=IO38 / DOUT=IO45 | ✅ 确认 | **不变** —— 同上 |
| PCA9557 三脚的用途与电平 | ✅ 确认 | **不变** |
| I2C：SDA=IO1 / SCL=IO2 | ✅ 确认 | **不变** |
| I2S DIN=IO12 | ❌ `[06BSP]` 写 `I2S_DI_IO=-1`（录音路径未启用） | **单一来源** —— 靠"录音能跑通"实证，不靠互证 |
| `BUILTIN_LED_GPIO = IO48` | ❌ `[06BSP]` 说 IO10 | ⛔ **已作废** —— 那是**立创的 LED 脚**；原理图确认本板 IO48 是 TF 卡 CMD |
| `DISPLAY_BACKLIGHT_OUTPUT_INVERT true` | ❌ | ⛔ **已作废** —— 实测为高电平点亮 |

**规律很清楚**：两个已证伪的取值，**恰好都是只有 `[小智]` 一家在说、
而 `[06BSP]` 沉默或反对的项**。凡 `[06BSP]` 也确认过的，结论全部站得住。

> 这反过来给了一条可操作的判据：
> **当"多个来源"其实同源时，凡是只有它在说话的地方，都应视同单一未验证来源。**

### 3.1 需要说明的是：**没有一条已实测的结论被推翻**

本项目所有关键引脚结论最终都是**上板实测**过的（屏幕出图、喇叭放声、
拉低 IO10 看 LED、原理图核对 TF 卡脚）。这次查明的是**文档里的论证方式有问题**，
不是**事实错了**。所以本次改动集中在措辞与溯源，不改任何代码取值。

### 3.2 它顺带解释了「厂家注释与硬件不符」

项目统计过「**四次**遇到厂家注释与硬件不符」。现在有了根因：
**那些注释描述的是另一块板。** 至少三次可用这一条解释：

1. `SetOutputState(0,0)` 标注"背光"（实为 LCD 片选 P0）；
2. `BUILTIN_LED_GPIO = IO48` 标注"板载LED引脚"（本板是 TF 卡 CMD）；
3. `DISPLAY_BACKLIGHT_OUTPUT_INVERT true` 标注"低电平有效"（本板高电平点亮）。

## 4. 为什么值得单独记一份

这一条是项目里 **G11** 教训的实例：

> **「两处一致」不等于「两个独立来源」。同源副本之间的一致，是零信息。**

它与 **A2**（引脚表抄错一位，凭空造出不存在的「C1 最大架构风险」）是同一个形状的镜像：

| | A2 | 本案例 |
|---|---|---|
| 病灶 | 把**二手表格**当真源 | 把**转抄的副本**当成独立来源 |
| 后果 | 结论建立在错前提上，越推越自洽 | 论证强度被虚高，弱来源顶了强来源的位置 |
| 共同点 | **都是「来源」这一层没查清** | 同左 |

真正的教训不是"粤嵌抄了立创"，而是：
**我们从不缺"多来源一致"这种话，缺的是对"来源是否独立"的检查。**
这类错误不会让结论立刻出错，它只是**悄悄地把证据等级调高了一档** ——
而本项目恰恰高度依赖"两个来源印证"这套论证。
