# 智能鱼缸 AI 生态监测系统

基于 **ESP32-S3** 的鱼缸监测终端：本地屏幕上显示水质与环境数据，异常时在界面标红并上报告警，
可以通过手机在巴法云上看数据，也可以**对着它说话**——语音由小智服务器识别，
AI 还能反过来**调用设备上的工具**读实时数据、控制摄像头拍照看图。

> 这是一个**边做边实测**的工程。本 README 里的每个数字都来自上板实测；
> 没做到的、没买的、跑不通的，都在「现状」一节里如实标出来。

## 快速开始

### 依赖

- Windows + PowerShell
- ESP-IDF **v5.5.3**，装在 `C:\Espressif`（本机同时装有 5.1.2 / 5.2.2，
  `build.ps1` 负责锁定 5.5.3 —— **不要直接调 `idf.py`**）
- 组件依赖由 ESP-IDF 组件管理器自动拉取（见 `main/idf_component.yml`）

### 构建与烧录

```powershell
.\build.ps1 build                 # 构建
.\build.ps1 -p COM10 flash        # 烧录（首次会自带字体分区，见下）
.\build.ps1 -p COM10 monitor      # 看串口
.\build.ps1 -p COM10 flash monitor  # 烧完直接看
```

⚠️ **串口号必须先确认**：这块板子有两个串口 —— `USB-SERIAL CH340K`（UART0 主控制台）
和 `USB 串行设备`（USB-Serial-JTAG 次控制台），**两个口输出同一份日志**，
且设备会**在两者之间重新枚举**。烧错口不会报错，只会"什么都没发生"。
`build.ps1` 现在会把你传的 `-p` 真正透传给 `idf.py`（并在日志里回显一遍）。

⚠️ **板子的 USB 会反复"卡死"**：用几次之后某个口会报"设备不正确"、
或能打开但写不进去（esptool `Write timeout`）。**换波特率、绕过 `idf.py` 直调 esptool 都没用**
——唯一有效的办法是**拔插 USB**。

### 首次烧录会多写一个分区

`idf.py flash` 除了 4 个常规镜像，还会往 **`0xD00000` 的 `fonts` 分区**写一个 1.9 MB 的
Noto 字体二进制。这是**中文缺字形**的修复（见下），由
`esptool_py_flash_to_partition()` 自动挂上，**不需要手工 esptool 命令**。

如果只想更新应用、不想重写字体：`.\build.ps1 -p COM10 app-flash`。

## 它是怎么组织的

```
main/                    任务创建与编排（app_main.c 是唯一的总入口）
components/
├── app_core/            共享数据模型 tank_ecosystem_t + 事件总线
├── board_gec/           板级真源：引脚、I2C 总线、PCA9557
├── lcd_display/         ST7796 驱动 + **唯一写面板出口 panel_send()**
├── esp_lcd_st7796/      面板驱动（自包含副本）
├── esp_lcd_touch*/      触摸抽象层 + FT6X36 驱动
├── touch_input/         触摸 → 事件
├── ui_lvgl/             LVGL 移植层 + 四个页面 ← **唯一接触 LVGL 的组件**
├── audio_service/       ES7210 / ES8311 + I2S 全双工
├── opus_codec/          Opus 编解码
├── camera_service/      esp32-camera 封装 + 互斥锁
├── sd_service/          TF 卡挂载 / 存照片 / 列照片 / 读缩略图
├── net_service/         Wi-Fi + 巴法云 MQTT + SNTP（凭据在这里，见下）
├── xiaozhi_client/      小智协议层：OTA / WebSocket / MCP / 视觉上传
└── font_service/        中文字体：普惠体 + Noto 回退
fonts/                   烧进 flash 分区的字体二进制（未提交到 app 里）
docs/                    引脚 / 协议 / 逐次会话的排障报告
```

**三条贯穿全局的纪律**（违反它们会出最难查的那类故障）：

1. **只有 `ui_task` 与 `ui_lvgl` 内部可以碰 LVGL**，且**慢动作绝不持 LVGL 锁**
   （拍照最长阻塞 4 秒、解 6 张缩略图要几百毫秒）。
2. **只有 `mqtt_task` 调 `esp_mqtt_client_publish`**，其他任务走 `bafa_mqtt_enqueue()`。
3. **慢操作绝不放在 WebSocket 回调里** —— 那跑在协议栈自己的任务上、栈很小；
   回调只入队，交给专用大栈任务。

## 几个值得知道的坑（都会**静默失败**）

这些是实际踩过、并且**在日志上完全看不出来**的：

| 坑 | 症状 | 真相 |
|---|---|---|
| 巴法云消息长度上限 | 发布返回成功、日志打"已发布"、**云端一片空白** | 官方文档没写这条。实测 18 字节能显示、209 字节一条都不显示，阈值落在 18~209 之间（128 最可能）。代码里有 `BAFA_PAYLOAD_SAFE_MAX` 守卫 |
| 巴法云主题名 | 同上，完全一样 | 主题必须先在控制台创建。名字对不上时发布**不报错** |
| 麦克风增益没设 | **上行发送全成功，服务器一条文本都不回** | 必须显式 `esp_codec_dev_set_in_channel_gain(..., 37.5)`。判据：上行**静音帧只有 2~5 字节，带声音是 108~113 字节/帧** |
| cbin 字体的 ABI | **渲染出乱码而不是报错** | 字形描述符大小由 `LV_FONT_FMT_TXT_LARGE` 编译期决定，字体 bin 与 sdkconfig 必须一致。`font_service.c` 里有 `_Static_assert` 钉着 |
| MCP 工具描述 | AI 答"都正常"，**而当时数据已越界** | 它报的是**过期的真数字**，从回答上根本看不出错。工具描述里必须显式要求"每次都要重新调用" |
| 串口日志 | 日志在某一处整齐停住，**看起来程序卡死了** | 抓取侧会断流。**"日志里没有"不等于"代码没执行"**，换一种抓法交叉验证 |

更完整的清单在 [`docs/peripherals-and-pitfalls.md`](docs/peripherals-and-pitfalls.md)
（按硬件/颜色/内存/并发/云端/工具链/方法论分了七类，逐条给了症状、真相与判据）
以及 [`docs/`](docs/) 的各份报告里。

## 中文缺字形（一个具体例子）

屏幕上的中文大部分来自 AI，**说什么不受控**。项目曾多次出现
`lv_draw_letter: glyph dsc. not found for U+6B38`，界面上少一个字。

根因不是"字体没加载"，而是：项目用的 `78/xiaozhi-fonts` 里的普惠体是**子集化**字体
（6649 个码位，其中 CJK 只有 **5258**），它是按「DeepSeek-R1 ∪ Qwen3 分词器字符」
裁剪的，**有 766 个字符普惠体里根本没有、被生成工具静默丢弃**。

修法：同一组件里另有一个覆盖大得多的 Noto 版（**CJK 10335** 个），把它放进
flash 的 `fonts` 分区，运行时 mmap 出来挂成普惠体的 **fallback**。
代价实测为 **内部堆 +420 字节**。

判据不靠肉眼看：`font_service_init()` 结束前会拿一个**已知缺失**的码位
（U+6B38）去问两个字体验证，直接打出结论：

```
I (3059) font: 自检通过：U+6B38 普惠体里没有、回退后取到了（16x16，来自Noto 回退）
```

细节与 ABI 判据见 [`fonts/README.md`](fonts/README.md)。

## 关于这份工程的一点说明

这个项目的方法是**每一步都要求可验证的判据**：

- 测试**本身**要先能自证（例如颜色自检会回读自己刚画的像素，而不是"看着像对的"）；
- 能用**不依赖人**的判据就不用依赖人的（麦克风好坏靠"板子自己响/静交替"比 RMS，
  而不是"人在正确时刻说话"）；
- **绝不写"在失败时也成立"的日志** —— 曾经有一条说反了的日志把整个排查方向带偏；
- 判错的结论**留在文档里**，连同它错在哪、怎么被推翻 —— 因为重复踩同一个坑的代价更大。
